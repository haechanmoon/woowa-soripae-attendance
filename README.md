# 소리패 시스템

밴드 동아리 **소리패**의 합주 출석을 관리하는 웹 앱입니다. 토이 프로젝트가 아니라 **부원 25명이 매일 쓰고 있는 운영 서비스**입니다. 출석 인증, 지각·결석 벌금 계산, 합주 스케줄 조율, 임원진 관리 기능이 들어 있습니다.

**현재 운영 중입니다.** HTTPS 도메인으로 서비스하고 있으며, 주소는 동아리 내부에 공유합니다.

기존에는 카카오톡으로 "저 왔어요" 사진을 올리고 임원이 수기로 지각 시간을 세어 벌금을 계산했습니다. 사람이 세는 이상 기준이 흔들리고 기록이 남지 않는 게 문제였습니다.

---

## 운영 현황

2026년 7월 27일 기준입니다.

| 항목 | 수치 |
|---|---|
| 등록 부원 | 25명 |
| 일 평균 접속자 | 약 15명 (최다 28명) |
| 누적 커밋 | 25개 / 8일 |
| 배포 횟수 | 10회 이상 |
| 테스트 | 139개 |

접속자 수는 **서버 로그의 고유 IP 기준 추정치**입니다. 정확한 DAU가 아닙니다 — 같은 와이파이를 쓰면 여러 명이 한 명으로 합쳐지고, 데이터 통신은 IP가 바뀌어 한 명이 둘로 셉니다. 실제로 부원이 25명인데 하루 접속자가 28명으로 잡힌 날이 있습니다. 이 한계를 알고 추세 파악용으로만 씁니다.

접속 통계는 브라우저에 심는 분석 도구 대신 **서버 로그를 직접 집계**합니다. 이 앱은 광고 차단기 때문에 API가 막힌 전력이 있어서, 클라이언트에서 수집하면 상당수가 집계에서 빠지기 때문입니다. 집계기는 `ops/soripae-stats.sh`에 있고 매시간 정적 HTML을 생성합니다.

## 기술 스택

**백엔드** · Java 21, Spring Boot 4.1, Spring Data JPA, Flyway, MySQL 8
**프론트엔드** · 바닐라 JS + Tailwind (SPA, 빌드 도구 없음), PWA
**인프라** · AWS EC2 (t3.micro), Nginx 리버스 프록시, Let's Encrypt HTTPS, systemd

프론트엔드에 프레임워크를 쓰지 않은 건 의도적입니다. 화면이 10개 남짓이고 실사용자가 25명인 규모에서 빌드 파이프라인을 들이는 비용이 이득보다 크다고 봤습니다.

---

## 도메인 규칙

출석과 벌금 정책이 이 서비스의 핵심입니다. 규칙이 한 곳에만 있도록 `FineCalculator`에 모아두었습니다.

- 정규 연습(코어타임)은 **13시 시작**
- **하루에 한 번 인증하면 그날 출석 인정.** 곡이 여러 개여도 한 번이면 끝
- 지각 기준 시각은 서버가 정합니다 — 그날 등록한 스케줄이 있으면 그 시각, 없으면 코어타임 13시
- 지각은 **분당 100원**, **60분 이상 늦으면 결석**으로 처리하고 **6,000원** 정액
- 스케줄 등록은 **다음 주만** 가능하고 마감은 일요일 자정. 마감이 지난 이번 주는 사유를 남겨야 바꿀 수 있습니다

## 구조

```
domain/          비즈니스 규칙. 웹 계층을 모른다
  attendance/      출석 인증, 벌금 계산 (FineCalculator)
  schedule/        합주 스케줄, 주 단위 집계 (WeekScope)
  member/          부원
  song/            곡 배정, 합주 시간 조율
  event/           공연·행사
web/             REST 컨트롤러 + 요청/응답 DTO
global/          예외 처리, 파일 저장, 설정
resources/
  db/migration/    Flyway 마이그레이션 (V1~V6)
  static/          SPA (HTML 1개 + JS 모듈 9개)
ops/             운영 스크립트 (접속 통계 집계기)
```

도메인 계층은 웹 계층을 참조하지 않습니다. 날짜 계산처럼 규칙이 얽히는 부분은 `WeekScope` 같은 값 객체로 빼내 요일 7개를 전부 넣어 검증합니다 — 구현을 그대로 베껴 기대값을 만들면 테스트가 아무것도 잡지 못하기 때문입니다.

## 테스트

```bash
./gradlew test     # 139개
```

테스트는 **인메모리 H2**를 쓰고 Flyway를 끕니다. 원래는 `@SpringBootTest`가 로컬 MySQL에 그대로 붙어서 `./gradlew test`만 돌려도 마이그레이션이 실행됐습니다. 파괴적인 마이그레이션이었다면 테스트를 돌린 것만으로 실제 데이터가 지워졌을 상황이라 분리했습니다. 자세한 경위는 [docs/decisions.md](docs/decisions.md#테스트가-실제-db를-건드리고-있었다)에 있습니다.

## 로컬 실행

```bash
# MySQL에 soripae_attendance 스키마가 있어야 합니다. Flyway가 나머지를 만듭니다.
./gradlew bootRun
```
